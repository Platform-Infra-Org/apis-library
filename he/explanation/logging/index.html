    לוגים¶

    הספרייה כותבת לוגים עם Loguru, בכל מקום, ועושה זאת דרך לוגר משותף יחיד שמוגדר פעם אחת. העמוד הזה מסביר איך זה עובד ובאילו מוסכמות זה משתמש.

    לוגר גלובלי אחד, שמוגדר בזמן ה-import¶

    בניגוד ל-logging של הספרייה הסטנדרטית (שבה כל מודול שולף לוגר משלו עם שם), ‏Loguru מייצא אובייקט logger יחיד שכבר נוצר מראש. כל מודול עושה:

    from loguru import logger

    …וכולם מקבלים את אותו אובייקט. הקונפיגורציה לא יוצרת לוגר חדש: היא משנה את ה-sinks של האובייקט המשותף הזה. הספרייה עושה את זה פעם אחת, כתופעת לוואי של ה-import, ב- _internal/utils/__init__.py:

    logger_config = Logger(settings.LOG_LEVEL)

    ‏Logger.__init__ מריץ שני שלבים (ב-_internal/utils/logger.py):

    • ‏setup_loguru(): ‏logger.remove() מסיר את ה-handler של ברירת המחדל, ואז logger.add(sys.stdout, …) מתקין sink צבעוני יחיד ל-stdout עם formatter מותאם (שמזהה בצורה חכמה את מיקום המקור) ברמה שהוגדרה.
    • ‏configure_uvicorn(): מתקין UvicornHandler שמעביר רשומות לוג של הספרייה הסטנדרטית ושל uvicorn לאותו sink של Loguru, כך שהלוגים של ה-framework והלוגים של הספרייה חולקים זרם אחד.

    מכיוון שזה רץ בפעם הראשונה שמשהו מייבא את fastapi_template._internal.utils (וכמעט הכול עושה את זה, בעקיפין), הלוגים מוגדרים לפני כל בקשה, ואפילו לפני חיווט האפליקציה.

    השלכות שכדאי להכיר¶

    • זה תלוי סדר, והכותב האחרון מנצח. הקונפיגורציה קוראת ל-logger.remove(), שמנקה את כל ה-sinks, כולל כאלה שהוספתם בעצמכם לפני שייבאתם את הספרייה. אם אתם רוצים sink משלכם, הוסיפו אותו אחרי ייבוא החבילה.
    • ‏LOG_LEVEL נקרא פעם אחת. ה-sink מתווסף עם level=settings.LOG_LEVEL פעם אחת בלבד, ולכן לשינוי המשתנה אחרי ה-import אין שום השפעה: הגדירו את LOG_LEVEL לפני שהתהליך עולה.

    מוסכמת הרמות¶

    המחברים הם הקוד עם הלוגים המקיפים ביותר, והם קובעים את סגנון הבית שלפיו פועלת שאר הספרייה (כולל האימות, ה-SSO וה-Remote Config API):

    רמה משמשת עבור
    INFO פעולות שגלויות למשתמש ומעברי מצב
    DEBUG קריאות פנימיות, לולאות תשאול, החלטות מטמון, פתרון מפתחות
    WARNING קונפיגורציה שגויה או התנהגות פגועה שאפשר להתאושש ממנה
    ERROR כשלים בשירותים חיצוניים: נרשמים ללוג מיד לפני זריקת השגיאה המוגדרת טיפוס

    רשומה יכולה להעביר extra={"location": "..."} כדי לדרוס את תווית המקור שמוצגת: לוגר הבקשות משתמש ב-"Request"/"Response", וה-middleware של האימות משתמש ב-"Auth".
